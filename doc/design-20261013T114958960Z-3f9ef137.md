# rs-model-metadata 与 rs-reflect v3 集成及校验能力扩展设计

## 基线与目标

本设计针对当前 Paseo workspace 中的 `/data/working/qubit/rust-common/rs-model-metadata`，基线为其 `dev-starfish` 检出。2026-10-13 的只读评审在该目录运行 `cargo test --workspace --locked --quiet`，编译因旧 `qubit-reflect` API 报出 16 个错误（退出码 101）。当前相邻 `rs-reflect` 的根模块已移除 `ReflectedRef`、`ReflectedMut`、`ReflectedOwned` 和 `reflect_impl`，公开动态值入口为 `qubit_reflect::value::{DynamicRef, DynamicMut, DynamicOwned, Local}`，过程宏入口为 `#[Reflect]`、`#[ReflectImpl]`。模型运行时 `src/__private.rs` 和 `derive/src/expand/model_impl.rs` 仍引用旧入口；`rs-platform` 的 `modules/model-runtime` 通过路径依赖消费本项目。两仓库仍声明 `qubit-reflect` 0.2.0，版本号本身不能保证相邻检出的源码 API 兼容。

目标按先后顺序为：

1. 当前相邻 `rs-reflect` → `rs-model-metadata` → `rs-platform` 依赖链能够编译、运行既有测试，并构建 Rustdoc；运行时与派生宏共同使用 v3 契约。
2. `validation` 能执行受支持的枚举载荷约束，以及常见集合的元素、MapKey、MapValue 约束和 validator；不支持的具体形状仍在计划构建期报告 `UnsupportedExecution`，保留字段、变体、选择器与源位置。
3. 英文与中文用户指南给出同一事实基础上的完整 codec 绑定场景，说明成功、缺少注册项、类型不匹配及应用仍需自行执行编解码；英文指南将核心实例校验路径放在进阶专题之前。设计文档的“可运行用法”承诺须由实际示例支撑。

用户允许破坏性变更，本轮不恢复旧反射宏或 `Reflected*` 兼容别名。保留当前业务语义、错误来源与无静默漏检原则。不要把工作目录中其他分支或 `rs-model-metadata-v3` 的未提交改动直接合并；它们只可作只读对照，须对当前源码重新验证。

## 方案选择

| 方案 | 判断 |
| --- | --- |
| 在 `rs-reflect` 恢复旧根导出和 `reflect_impl` | 会长期维护两套 API，且不能解决字段读写与宏 ABI 的真实变化；不采用。 |
| 直接复制候选迁移工作树 | 候选树有大量未提交修改，可能覆盖当前目标项目的独立改动；不采用。 |
| 在目标项目按 v3 契约迁移运行时与宏，再独立扩展校验执行 | 改动可按编译、行为、文档逐层验证；采用。 |

## 边界一：反射 API 迁移

运行时继续负责模型语义，`rs-reflect` 继续负责结构描述和安全的动态字段访问。`src/__private.rs` 是生成代码的唯一私有门面：它转发当前 `ReflectImpl` 宏与必要的 v3 类型，不向应用承诺该门面的稳定性。`PropertyValue`、getter/setter adapter、路径读写和校验输入统一使用 `DynamicRef<'a, Local>`、`DynamicMut<'a, Local>`、`DynamicOwned<Local>` 或普通 Rust 引用/值。局部值允许非 `Send`/`Sync` 类型；不得无证据地强制改成 `ThreadSafe`。从 `FieldDescriptor` 读取时使用当前的 `get_dynamic`、`get_mut_dynamic`、`set_dynamic` 等受检入口；需要静态类型且已知 `T`、`V` 时使用普通 `get`、`set`。迁移必须保留原有类型不匹配、写入前拒绝和 setter 已执行后的失败恢复语义。

`derive/src/expand/model_impl.rs` 将 `#[ModelImpl]` 所生成的反射 impl 标注改为 `#[ReflectImpl]`；getter/setter adapter 的签名、构造器和生成 ABI 与运行时一同更新。`derive/src/expand/fields.rs` 的字段 adapter 同步更新。先用运行时和派生宏中的旧符号搜索建立调用点清单，按编译错误逐处迁移；`E0282` 等推断错误在旧类型消失后重新判断，不先加无意义显式类型掩盖根因。若当前 v3 接口缺少必需的受检操作，优先在 `rs-reflect` 提供窄的安全 API，再消费；不得复制私有布局或使用 `unsafe` 绕过检查。跨仓库改动必须单独记录精确接口与验证结果。

生成代码的 `__private::v7` 只是现存私有 ABI 名称。若签名改变，运行时与宏必须同步更新 ABI 版本或加入编译期失配诊断，不能让旧宏静默链接到新运行时。具体版本号在实现时按当前源码与测试确认，文档只承诺二者必须一致。

## 边界二：校验执行能力

声明遍历、访问能力检查、绑定、实例执行继续分阶段。`ValidationCapabilities::check` 与 `ValidationPlan::build` 对同一形状应得出相同的支持判断；执行器只运行已绑定的 occurrence。构建成功不得遗漏实际声明。现有 `ValidationBuildError`、`ValidationPath`、部分报告和预算语义保持不变。

### 枚举载荷

支持具名与位置载荷字段上的直接文本、数字、时间等已可用于普通字段的规则及自定义 validator。计划对每个变体保留变体索引、字段索引和声明顺序；实例执行先判定活动变体，只执行该变体的字段规则，未活动变体不产生“缺失值”违例。字段读取须通过 v3 的受检反射字段入口或生成的安全 variant adapter；若现有 `VariantDescriptor::is_active` 无法接受动态根，则为模型生成窄的活动变体 adapter，或在 `rs-reflect` 补受检动态入口。活动变体判断失败属于执行错误，附已有部分报告；不能把错误当成非活动变体。错误路径显示变体与字段，例如 `Named.name` 或 `Pair.0`。

### 集合内部选择器

第一批执行形状限定为生成器能证明并生成借用遍历 adapter 的 `Vec<T>`、固定数组、切片，以及 `HashMap<K,V>`、`BTreeMap<K,V>`；外部自定义容器和无法借用元素的 getter 继续返回 `UnsupportedExecution`。`Element`、`MapKey`、`MapValue` 的标准约束与无外部依赖的 validator 在每个实际成员上执行，顺序为声明顺序、随后集合遍历顺序；HashMap 的成员顺序不保证跨进程稳定，报告携带实际遍历时的条目序号，不承诺稳定排序。Map 的同一条目先 key 后 value。空集合不产生内部元素违例，但外层长度与去重规则仍执行。`Option` 为 `None` 时沿现有跳过语义，不访问内部。新 adapter 只返回借用值，调用方不能保存超过源实例生命周期。每次成员访问和规则调用计入现有节点、深度、比较及违例预算；预算耗尽仍返回含部分报告的执行错误。若声明含当前不支持的依赖绑定或嵌套容器形状，构建期明确拒绝且保留选择器位置。

为此扩展 `CollectionOps` 或同层的私有执行 adapter，使 derive 在具体字段处生成安全的元素或 map 遍历能力；不要让 `validation` 针对任意 `dyn Any` 猜测容器实现。该扩展若触及公开构造器或 `__private` ABI，允许做破坏性签名调整，并同步所有手写 fixture、基准和测试。先保持现有 `MapLenAdapter`、`ItemEqAdapter` 语义，再增加遍历入口，避免外层 map/sequence 规则回退。

含可执行工作的递归路径仍明确拒绝，本设计不定义无限递归的终止策略。未列明的 tuple/自定义容器同样保持明确拒绝；后续能力扩展需独立设计。

## 文档与验证

英文和中文运行时指南各增加一个使用公开 API 的完整 codec 示例，复用 `tests/codec_binding_tests.rs` 中已证实的注册方式。代码从 `#[codec(...)]` 声明、`ValueStringCodecRegistry` 注册、图构建走到 `bind_codecs`，检查绑定的 occurrence；另给缺少注册项的可观察错误。示例明确 codec 绑定不自动执行序列化或持久化。中英文可分别组织文字，但输入、预期结果和限制一致。将两份示例加入现有 `tests/documentation_examples_tests.rs` 的 Markdown fence 验证。英文指南的核心实例校验段移至首次元数据与图操作之后，再排列字段身份、路径和适配器等进阶内容；锚点链接同步更新。README 保留简短价值、最小示例和指南入口，不复制长教程。中英文设计文档同步更新新的校验支持矩阵和限制。

验证顺序为：当前 `rs-reflect` API 核对 → 目标项目默认与全 feature 编译、运行时/derive/trybuild 测试 → codec 与新增校验回归 → 双语文档示例、链接检查、Rustdoc → `rs-platform` 的 model-runtime 与相关消费者测试 → 仓库现有 CI、Clippy、风格门禁。重型 Cargo 命令串行运行，避免同一 `target` 锁争用。记录每条命令、退出码和实际提交；历史覆盖率文件不能替代本轮验证。

## 验收标准

- 当前相邻检出的 `cargo test --workspace --locked` 与 `cargo test --workspace --all-features --locked` 通过，且生成代码搜索不再依赖已删除的应用级 v3 入口。
- 枚举活动变体、位置/具名字段，集合元素、map key/value 的有效值、违例、空值、错误与预算边界有正反测试；不支持形状仍在构建期明确拒绝。
- `rs-platform/modules/model-runtime` 及至少一个真实模型消费者通过聚焦验证；若下游因公开 API 破坏需要调整，仅修改受影响调用点并记录迁移。
- 中英文 codec 示例可从文档原文编译运行；文档链接检查、Rustdoc 和项目风格门禁通过；报告不把“绑定成功”写成“完成编码”。
