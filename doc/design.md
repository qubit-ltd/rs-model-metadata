# rs-model-metadata design

[简体中文](design.zh_CN.md) · [User guide](user_guide.md) · [Derive design](../derive/doc/design.md)

This document describes the implemented `qubit-model-metadata` 0.2.0 crate (Rust 1.94, edition 2024). It is the runtime metadata and resolution layer; declarations are generated by `qubit-model-derive`, while applications decide how to persist, query, and validate values. The package is currently `publish = false`.

## Boundaries and data flow

```text
Rust declarations --derive--> TypeMetadata + reflect capabilities
                              |
ReflectRegistry snapshot ----> ModelRegistry ----> StructureResolver ----> ModelGraph
                                     |                    |
                             PropertyAccessPath     optional validation/codec binders
```

`TypeMetadata` describes one Rust type's role, fields, declarations and local properties without an instance. `FieldMetadata` describes stored fields; `PropertyMetadata` combines a field with eligible `ModelImpl` getters and setters, or represents a computed property. Property values borrow the source instance when possible. `FieldLocation` identifies an actual field by owner `TypeId`, optional enum variant and field index; a generic definition field has no concrete location. `ModelId` is the stable external identity, whereas `TypeId` and `FieldLocation` are process-local identities.

The public vocabulary lives in `metadata`, `registry`, `resolve`, and `access_path`. `generic`, `validation`, and `codec` are separate optional features; the default feature set is empty. The independent `qubit-model-id` crate carries the stable ID protocol.

## Snapshot and graph ownership

`ModelRegistry::try_global()` freezes linked reflection registrations once and retains initialization errors. An explicit registry can instead project one supplied `ReflectRegistry` snapshot or accept static metadata. The registry indexes stable IDs and exact Rust types; anonymous roots are supplied to the resolver and never receive invented IDs. Its property and metadata caches are scoped to that registry. Its bounded property-path cache retains up to 256 successful compiled paths across read and write modes; failed compilations are retried. A compiled path already held by a caller remains usable after cache eviction.

`StructureResolver::new` audits all registered models; `for_roots` and `for_static_roots` build only the roots' reachable graph. Resolution checks roles, references, projection sources, value closure, unique scopes and query declarations. `ModelGraph` borrows the selected registry and exposes resolved relations by `TypeId` or `FieldLocation`. A metadata-only registry must be supplied with child metadata explicitly; a reflection-backed snapshot can discover reachable anonymous children. A graph never imports missing declarations from a global registry.

## Declaration and execution split

The core stores constraints, validators, selectors, codec references, object paths and property paths as declarations. Object paths use `/` and `..`; property paths use `.`. Query metadata exposes declarations and reasons but does not expand arbitrary consumer filters. `PropertyAccessPath` compiles structural traversal, then reads or writes an instance; read and write capabilities differ. Structural failure is reported before invoking a leaf setter. An application remains responsible for authorization, persistence and query execution.

With `validation`, `ValidationCapabilities::check` inspects whether a root's declarations can execute. `ValidationPlan::build` binds supported occurrences against a caller-supplied `ValidatorRegistry` and an `Arc<ModelGraph>`; it returns aggregated build errors for unsupported shapes or missing rules. `validate` returns a report for rule violations and a `ModelValidationError` with a partial report for execution failures. `ValidationOptions` controls selection, stopping policy and budgets. Optional codec binding likewise requires explicit registries. The precise support matrix and runnable workflow are in the [user guide](user_guide.md#limitations-execution-support-and-explicit-refusal).

## Error and compatibility contracts

Macro syntax errors occur at compile time. Checked metadata construction and registry initialization report ABI or registration errors. Graph resolution reports structural errors; execution adapters report binding or runtime errors. A missing lookup is distinct from a failed lookup. Generated constructors use the synchronized `__private::v7` ABI and the reflection provider contract; runtime and derive versions must be kept together. Persist `ModelId`, never a process-local `TypeId` or `FieldLocation`.

The platform's production integration is described in the [rs-platform design](../../rs-platform/doc/design.md). Historical requirements and migration ledgers remain background records, not a substitute for these current contracts.
